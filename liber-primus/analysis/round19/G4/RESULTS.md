## 1. Headline

**All four generators reproduce the real TeX output element-for-element, first time, across
15 808 elements — and the era question is moot, because pgf's generator has not changed since
2007.**

```
  pgf / pgfmath   \pgfmathgeneratepseudorandomnumber
                  Lehmer  m=2^31-1  a=69621  q=30845  r=23902     <- NOT 16807
                  default seed = \time x \year
  lcg (v1.3)      \rand
                  Lehmer  m=2^31-1  a=16807  q=127773 r=2836  + rejection
  random.tex 0.2  \nextrandom / \setrannum
                  same Lehmer core; DIVISION-scaled reduction + rejection; 3 warm-up draws
  pdfTeX 1.40     \pdfuniformdeviate / \pdfsetrandomseed
                  Knuth 55-lag subtractive on 28-bit fractions; seed space collapsed to 2^28
```

Three consequences that change the shape of the search, not just its size:

1. **pgf's multiplier is 69621, not 16807.** The Numerical-Recipes 16807 appears in
   `pgfmathfunctions.random.code.tex` only inside a comment listing *alternative* parameters. A
   reimplementation that took the comment at face value would have swept the wrong stream and
   reported a meaningless null. This is precisely the failure mode the byte-exact gate exists
   to catch.
2. **The offset ladder is absorbed.** Both multipliers are primitive roots mod 2³¹−1 (verified:
   `a^((m−1)/p) ≢ 1` for every prime `p | m−1 = 2·3²·7·11·31·151·331`, and the state returns to
   its seed after exactly `m−1` steps and not at `m−1)/2`). Each generator therefore has **one
   cycle**, so *every seed and every offset is a phase of one master stream*. B-04's 10-entry
   offset ladder and B-02's key-index-0 assumption are **absorbed, not merely swept** — the
   first generator family in this repository where that is true.
3. **The instrument, not the space, is the binding constraint.** I1's repaired `drift` preset
   costs **0.679 s/decode** of beam time versus **0.0030 s** for the repo's `exact` preset —
   **226 ×** — and **36.5 ×** end-to-end once I2's adjudicator is counted (0.619 vs 0.0170 s,
   measured over 10 000 real decodes). At `drift` rates the whole 1.85 × 10¹¹-decode space is
   ≈ 3 700 years on six cores. What makes it tractable is that three of the four families are
   **one cycle**, which turns enumeration into a sliding-window scan: **≈ 18 hours**, measured
   rather than estimated (§5.4), and conditional on a prefilter whose power nobody has
   measured yet.

## 2. Which TeX is era-correct, and does it matter

Ubuntu 11.04 / 11.10 / 12.04 LTS — the platform window L1 fixed from GnuPG 1.4.11 (F6/F7) and
the ImageMagick-over-Ghostscript stack (F1/F2) — all ship **TeX Live 2009**, whose pgf is
**2.00**. A user installing from CTAN from October 2010 onward had **pgf 2.10**.

Both were fetched (`fetch_sources.sh`, into gitignored `vendor/`) and diffed:

| comparison | result |
|---|---|
| pgf 2.00 `pgfmathrnd.code.tex` vs pgf 2.10 `pgfmathfunctions.random.code.tex` | **`\pgfmathgeneratepseudorandomnumber` byte-identical.** The only differences are `\pgfmathdeclarefunction` renames and the addition of the `random(a,b)` parser hook |
| pgf 2.10 vs current CTAN pgf 3.1.x | generator identical; current adds a `z = 0 → z = 1` guard on the default seed |
| **reference vectors** generated by pdflatex under vendored **pgf 2.10** vs installed **pgf 3.1.11a** | **76 / 76 vectors identical** (gate V3 PASS) |

**So the era question does not bite for this lane.** It would have bitten for a package whose
RNG changed; it did not for pgf, and `lcg` v1.3 is dated 2013/08/09 — inside the window.

One measured surprise: `\pgfmathsetseed` routes through `\pgfmathparse`, which is a fixed-point
parser, so one expects a seed cap near 16 383. **There is none** — pgf 2.10 and 3.1.11a both
store `2147483646` verbatim (`tex/ref_pgf.txt`, `SEEDACCEPT` lines). The full 2³¹−2 seed range
is reachable from a document.

## 3. Exact parameters, with source citations

All paths are inside `vendor/` (rebuildable by `fetch_sources.sh`) or the WSL TeX Live tree.

### 3.1 pgf — `vendor/pgf_2.00src/pgf-2.00/generic/pgf/math/pgfmathrnd.code.tex`

```tex
\def\pgfmath@rnd@m{2147483647}   % 2^31 - 1
\def\pgfmath@rnd@a{69621}
\def\pgfmath@rnd@r{23902}
\def\pgfmath@rnd@q{30845}
\begingroup \c@pgfmath@counta=\time \multiply\c@pgfmath@counta by\year
            \xdef\pgfmath@rnd@z{\the\c@pgfmath@counta} \endgroup   % the default seed
```

Transition (Schrage): `hi = z div q ; lo = z − q·hi ; z' = a·lo − r·hi ; if z' < 0: z' += m`.
`\pgfmathrandominteger{\x}{lo}{hi}` takes **one** draw and returns `lo + (z mod (hi−lo+1))`,
so `{0}{28}` and `{1}{29}` are the same residue stream differing by a constant 1.
`\pgfmathparse{int(rnd*29)}` is a **different** stream: `rnd` is `(z mod 100001)` rendered as a
5-decimal number and stored in a dimen (quantised to 1/65536 pt). Both are implemented and both
validate.

### 3.2 `lcg` v1.3 — `vendor/lcg.dtx.ctan`

```tex
\divide \@tempcnta 127773   \multiply \@tempcnta -2836
\multiply \@tempcntb -127773 \advance \cr@nd \@tempcntb
\multiply \cr@nd 16807       \advance \cr@nd \@tempcnta
\ifnum \cr@nd < \z@ \advance \cr@nd 2147483647 \fi
```

Park–Miller `a=16807, q=127773, r=2836`. `\rand` then **rejection-samples**: with
`R = last−first+1`, `lim = R·(m div R)` (= 2 147 459 628 for R = 29), redraw while `z > lim`,
else return `first + (z mod R)`. Rejection rate for R = 29 is 24 019 / (2³¹−1) = 1.1 × 10⁻⁵.
Default seed (unset): `(((time + inputlineno)·page + year)·month·day) + inputlineno`.

### 3.3 `random.tex` v0.2 — `vendor/random.tex.ctan`

Same Lehmer core, **different reduction**:
`B = 2147483645 div R` (= 74 051 160 for R = 29); draw `z`, `v = (z−1) div B`, accept iff
`v < R`, return `v + lo`. Default seed `((time·388 + year)·31 + day)·97 + month`, followed by
**three discarded warm-up draws**. That warm-up is the sort of detail a reimplementation
silently drops; gate **V6** checks it against a live `pdflatex` run and **PASSES**
(`seed 847296948 → 2101389952` after four steps, predicted = observed).

### 3.4 pdfTeX — `\pdfuniformdeviate` / `\pdfsetrandomseed`

Not named in the lane brief; added because it may be the most idiomatic of the four. It is a
**primitive of the engine** (no package to load), present since pdfTeX 1.30 (2005) and therefore
in TeX Live 2009, and `\pdfuniformdeviate{29}` returns 0…28 in one call — literally "give me a
random rune index". Algorithm is METAFONT's: `randoms[55]` of 28-bit fractions,
`new_randoms` subtractive lags 31/24, `init_randoms(seed)` with `j = |seed|; while j ≥ 2²⁸: j //= 2`
(**which collapses the seed space to 2²⁸**), three warm-up `new_randoms`, and
`unif_rand(x) = take_fraction(|x|, randoms[j_random])` with `take_fraction(p,q) = (p·q + 2²⁷) >> 28`.

Validated against `\pdfuniformdeviate{268435456}` (which returns the raw 28-bit fraction),
`{29}` and `{256}` — the three together pin the state, the reduction and the rounding
independently. All three PASS.

### 3.5 LuaTeX `math.random` — declared a duplicate of G1, not swept here

LuaTeX embeds Lua 5.1/5.2, whose `math.random` is the platform C `rand()` and whose
`math.randomseed` is `srand()`. On glibc that **is** `random()`, the TYPE_3 additive-feedback
generator — **G1's space, not G4's**. Sweeping it here would be a duplicate. What G4 contributes
is the *scaling*, which G1 should carry: Lua 5.1 computes
`floor(((rand() % RAND_MAX) / RAND_MAX)·(n−m+1)) + m`, **not** `rand() % 29`. Era note: LuaTeX
was beta in TeX Live 2009 and implausible as the engine for a book-length 2013 document.

### 4.1 The V5 failure is a real finding, and it is reported as one

`control.py` planted a pad **taken from the real pdflatex run** (seed 3301, `pgf_mod29`),
enciphered 120 runes of LP-style English with the repo's pinned `encipher_keyskip(supp=0.83)`,
and enumerated 20 001 phases × sign × atbash = 80 004 decodes, ranking by **exact rune agreement
with the known plaintext** — ground truth, not an English score, so the control borrows no power
from the instrument Round 18 measured as broken.

| measurement | value |
|---|---|
| Python pad == real-binary pad | **true** |
| key skips consumed by the filter over 120 runes | **2** |
| rigid argmax | phase **+2**, agreement **0.3917** |
| planted phase | rank **#2 of 80 004**, agreement **0.3833** |
| wrong-phase null (n = 200) | mean **0.0342** (1/29 = 0.0345), max **0.0917** |
| **beam at the planted phase** | **char recovery 1.0000**, translit `THEPRIMESARESACREDTHETOTIENT…` |
| beam score at the planted phase | −4.2247 *(recorded, not a decision statistic)* |

The pre-registered criterion asked for rigid rank 1 at agreement 1.00. That is **unattainable by
construction**: the filter advanced the key by 2, so the best *rigid* alignment is necessarily
the planted phase advanced by 2. I wrote a gate that required the rigid decoder to be exact for
a cipher L7-B says it cannot be exact for — a small instance of Round 19's own thesis, inside my
own control. The addendum records it; the criterion was not quietly edited.

**And it produced the most useful thing this lane found for Phase 2:** a phase prefilter must
retain a **band**, not a point. A top-K cut that keeps isolated maxima can discard the true
phase while keeping its neighbour. `READY.md` §3.3 makes that a hard requirement on the cut, and
budgets the 81× inflation it implies at `max_skip = 40`.

## 6. Side-deliverable — is LP2 plausibly `allrunes`-typeset?

_Evidence for L1's attribution profile. Reported separately, and it is a **screen, not a
verdict**._

Round 18's L1 left **NC-5** open with this reason: *"The `allrunes` Type-1 faces are in the bank
as files but are custom-encoded (not Unicode-mapped), so matching them requires an unordered
glyph-slot search rather than a codepoint lookup."*

**FOUND-ERROR: that reason is false for the files L1 already holds.** The 218 `.pfb` faces in
`round18/L1-toolchain/fonts/allrunes/allrunes/type1/pfb/` carry **ordinary Adobe glyph names
that are the transliteration letters themselves** — `f u eth o r c g w h n i j p x s t b e m l
eng oe d a ae y` — so **26 of the 29 futhorc runes are a direct name lookup and no unordered
slot search is needed.** Only EO / EA / IA lack an unambiguous name and were dropped rather
than guessed. **NC-5's stated blocker can be struck; the matching L1 wanted is a `fontTools`
call away.**

`allrunes_probe.py` then did that match, on the same quantity L1 measured off the pages (ink
bounding-box width, heights normalised to L1's 114 px), fitting one horizontal scale per face:

| | |
|---|---|
| faces carrying all 26 named runes | **72** of 218 (146 lack at least one and were skipped, not guessed) |
| best fit | `fruabr`, RMS **6.64 px** on widths spanning 10 → 86 px |
| order-destroying control (200 permutations of the observed width vector, refit each time) | null min **10.11 px**, median **15.30 px**, **p = 0 / 200** |

**What that supports:** the per-rune width assignment in the allrunes Anglo-Frisian family
matches LP2's observed assignment far better than chance, i.e. LP2 is **consistent with** an
allrunes-family face.

**What it does NOT support, stated plainly:** any *correct* futhorc rendering has narrow I and
wide X, so the permutation control discriminates "a real futhorc" from "a shuffle" — it does
**not** discriminate `allrunes` from Noto Sans Runic or any other correct face. L1 already
measured that the top of its own ranking was a tie among near-misses (0.23 σ). The fitted scale
factors (0.40 – 0.84) are an artefact of normalising by each face's *median* glyph height and
**must not be read as evidence of a condensed face**; L1's F5 condensation finding stands on
its own measurement, not on this one.

**The measurement L1 should now run:** its own `font_match.py` distance, with these 72 allrunes
faces in the bank, under PC3a/PC3b. That is now a codepoint lookup, and it is the cheapest
remaining route to naming the face.

## 9. Bounds, not verdicts

* **Not covered:** the entire 1.85 × 10¹¹-decode space. G4 delivered the generators; it swept
  nothing.
* **Reopens / proceeds if:** K2 passes (a planted phase survives a 10⁻³ rigid prefilter cut in
  ≥ 50 % of 200 trials), in which case the Lehmer families are ≈ 20 h of wall clock away from
  *complete* enumeration.
* **Also reopens if:** a source PDF/PostScript with an embedded font subset surfaces (L1 NC-6);
  or an `allrunes` shape variant is pinned (§6), which would pin the LaTeX source and with it the
  plausible package set; or evidence of per-page reseeding appears.
* **What would make this lane worthless:** the pad coming from `/dev/urandom`, or from a program
  outside the document. Both remain live. This lane does not claim otherwise — it claims that a
  branch nobody had considered is now enumerable, validated, and ~20 hours wide.
