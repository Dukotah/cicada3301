# Round 27 / P1 — grind27: build, run, resume, status

C port of the R25 Py2.7-MT 2^32 stage-A screen (SPEC: `../P0-spec/SPEC.md`, authoritative).
The engine makes **no hit decision**: its only filter is the candidate bar 5.0 and every
seed at/above it is appended to `candidates.jsonl` for Python (`hitfn20`) to adjudicate.
Verified 2026-09-07: V1 64/64 vector-exact (worst |Δpmax| = 0.0), V2 planted screen exact
(pmax 17.931158509762, margin 12.93 over bar), V3 drill exact (2149309687 →
6.82583546184365), K4 cross-check 95/95 C-flagged candidates re-scored by
`runner.stage_a` with **zero** relative difference.

## Build

```bash
cd liber-primus/analysis/round27/P1-engine
python3 export_data.py        # regenerates engine.dat + panel_lm.f32 (see below)
gcc -O3 -march=native -fopenmp -std=gnu17 -ffp-contract=off -o grind27 grind27.c -lm
./grind27 --self-test         # MUST print V1 PASS + V2 PASS and exit 0
./grind27 --drill             # V3: band [2149309680,2149309700) → 2149309687 @ 6.8258…
```

`-ffp-contract=off` pins FP semantics (no FMA contraction); the only contraction site
(`genrand_res53`) is value-identical either way, but we do not rely on that.
Do NOT add `-ffast-math` — it breaks bit-parity with Python.

## Input data (what the engine loads, and where it came from)

The engine does **not** re-derive the ciphertext. `export_data.py` flattens the frozen P0
artifacts into two files the C engine reads at startup:

| file | contents | provenance |
|---|---|---|
| `engine.dat` | C_SCREEN[120], panel mu/sd at n=120, candidate/claim bars, planted stage-A construct, all 64 V1 reference vectors, paths | `../P0-spec/vectors.json` (generated by `make_vectors.py` from the R25 pipeline verbatim) |
| `panel_lm.f32` | 9×24389 LE float32, register-major | `round19/I2/models/panel.npz` — the SAME panel.npz that generated vectors.json; sha256 recorded inside `engine.dat` (`14a23d3619fa02df…`) |
| `data/english_quadgrams.txt` | parsed directly by C with the exact `lp/score.py` arithmetic (log10(c)−log10(total), floor log10(0.01)−log10(total)); total+floor cross-checked against engine.dat at load | repo data file |

All doubles in `engine.dat` are Python `repr` strings; C `strtod` reconstructs
bit-identical values. `grind27`, `engine.dat`, `panel_lm.f32` are all regenerable —
gitignore them; commit the sources (`grind27.c`, `export_data.py`, this file).

## The sweep (unattended, resumable)

```bash
mkdir -p run
nohup ./grind27 --plan ../sweep_plan.json --run-dir run > run/grind.log 2>&1 &
```

* Executes the plan's lanes **sequentially** (S1 then S2 …), each split into 6 contiguous
  per-worker bands. The planted self-test runs at every launch (PREREG K3) and aborts the
  run if it fails.
* **Checkpoint**: `run/STATUS.json` (atomic tmp+rename, one small write every ~30 s;
  progress_w-compatible per-worker records), plus `run/hist_<lane>.u64` (per-worker pmax
  histogram, 0.01 bins over [0,26), uint64 LE) and `run/top_<lane>.json` (global
  top-1024 seed/pmax) — the SPEC §6 language-agnostic aggregates.
* **Resume**: just re-run the same command. Cursors, histograms, top-list and the
  completed-lane list reload from the run dir; completed lanes are skipped. Verified:
  interrupt at 427,514 seeds + resume = exactly 600,000 done, no gap, no double-count.
  SIGINT/SIGTERM checkpoint cleanly. `--seconds N` time-boxes a run (smoke tests).
* **Candidates**: every seed with pmax ≥ cand_bar (5.0 — 0.88 below the recommended
  claim_bar−1.5 margin; nothing near the bar is ever dropped) appends
  `{"lane","seed","pmax"}` to `run/candidates.jsonl` (fsync'd at checkpoint cadence).
  A seed at/above the lane claim bar ADDITIONALLY lands in `run/HIT-CANDIDATE.json`
  (FLAGGED-FOR-ORACLE, never auto-certified — R21-L1) and the sweep KEEPS GOING;
  Python `runner.stage_b` adjudicates offline/concurrently, tailing the JSONL.

```bash
./grind27 --status --run-dir run     # cheap poll: prints STATUS.json (no worker contact)
./grind27 --bench 600000 --threads 6 # throughput measurement
```

## P2 ENGINE-CONTRACT modes (added 2026-09-07 after the P2 gate FAILed the original CLI)

The binary also implements the harness contract (`../P2-harness/ENGINE-CONTRACT.md`)
verbatim — `--vectors`/`--lm` are accepted (data actually loads from `engine.dat`, which
is exported FROM vectors.json; `panel_lm.f32` sha256 is verified by check_vectors):

```bash
./grind27 --vectors V --lm LM --mode score --seeds seeds.txt --out out.jsonl [--full] [--cipher c.json]
./grind27 --vectors V --lm LM --mode sweep --band-start A --band-end B --threads N \
          --out cands.jsonl [--cipher c.json] [--progress-dir D]   # + stdout JSON summary
./grind27 --vectors V --lm LM --mode self-test                     # runs full V1+V2, then
          # prints {"mode":"self-test","seed":777,"pmax":…,"candidate":true}; rc 0 iff PASS
```

`--cipher {"cipher_idx":[…]}` overrides C_SCREEN with the first 120 entries; the
step tables are **rebuilt for the override** (StepTab is cipher-dependent — same lesson
as the V2 planted screen). `--mode score --full` adds ks128/plain_idx/ptr_end/n_skips/
nchars; pmax always prints `%.17g`. Unknown args now exit rc 1 (2 is the harness's
BLOCKED code). Harness acceptance 2026-09-07: `bash ../P2-harness/run_all.sh` → OVERALL
PASS rc=0 (validate.py, check_vectors, check_drill A+B, check_false_reject 100k G1–G4,
check_r25_repro, bench 130.4k seeds/s aggregate / ETA 9.15 h per 2^32 lane).

Additionally, `--plan` now REFUSES to start an `exact`-relation lane (S2) until its own
planted control + vector file exist (PREREG S2 gate; the launch-time self-test only
validates the `pair` relation). Override, once the control is validated, with
`GRIND27_S2_CONTROL_OK=1`.

## sweep_plan.json format

Ordered JSON array; fields per lane: `lane` (name), `reducer`
(`random29|grb5_mod|grb5_rej|shuffle29`), `relation` (`pair` = keyskip2/max_skip 8,
`exact` = keyskip1/max_skip 3), `offset` (key offset o), `from`/`to` (seed range),
optional `cand_bar` (default 5.0) and `claim_bar` (default: pair 7.383520294328688,
exact 7.6341931878728095). sign is −1 always. **Gate:** per PREREG, S2 (and any S3 cell)
needs its own planted control + vector file validated before its null counts; the engine
sweeps it mechanically either way.

## Measured throughput (2026-09-07, 6-core WSL2, i-series laptop)

* single thread: 32.4k seeds/s; 6 threads burst: **158k seeds/s** (88× Python's 1800/s)
* 6 threads sustained (60 s): **104k seeds/s** (58×) — the box thermally throttles under
  sustained all-core load; this is an environment property, not engine cost.
* 2^32 per lane ≈ **7.5–11.5 wall-hours** depending on throttle state.
* Candidate rate on noise: 532/6M = 8.9e−5/seed vs Gumbel prediction 6.95e−5 (1.28×,
  inside PREREG K2's [0.2×, 5×] band).
* The task's stretch target (180k aggregate) is reached only in burst; the SPEC §7
  conservative target (≥30k aggregate) is exceeded 3.5× sustained. PREREG K1
  (<2k/s/core) is nowhere near.

## What this engine must NOT do (SPEC §9)

No hit decision, no recovery computation, no held-out logic, no auto-certification.
The claim-bar comparison exists ONLY to raise the HIT-CANDIDATE flag file; it never
gates, stops, or rejects anything. Python remains the adjudicator of record on every
candidate. Re-run `--self-test` after ANY change to the hot path.
