## 0. Architecture — two-stage, C screens / Python adjudicates

```
C engine (new, this round)                      Python (existing, unchanged)
──────────────────────────                      ────────────────────────────
seed w ──► MT19937 keystream (784 runes)
       ──► keyskip2 'pair' beam decode
           (L=120, beam_w=64) of LP2[0:120]
       ──► panel-max pmax (plain doubles)
       ──► if pmax >= CAND_BAR (5.0):
             append {seed, pmax} to  ────────►  runner.stage_b(w, 1e6)
             candidates.jsonl                   = hitfn20 3-clause gate at L=240,
                                                beam_w=400: pmax>=7.3835... AND
                                                recovery>=0.90 AND held-out-3/4>=0.90
                                                ──► HIT ⇒ FLAGGED-FOR-ORACLE only
```

**Why this kills the float-parity problem.** The C engine makes NO hit decision and NO
rejection near the claim bar. Its only filter is the candidate bar **5.0** — the same
`SCREEN_BAR` R25 ran, and 0.88 *below* the recommended `claim_bar − 1.5 = 5.8835` margin.
Any C/Python float divergence would have to move a score across a ≥ 2.38-sigma-equivalent
gap (claim bar 7.3835 − cand bar 5.0) to false-reject; measured divergence on identical
arithmetic order is ~1e-13 (numpy pairwise-mean vs naive sum). Python (`hitfn20`) remains
the adjudicator of record on every candidate. A hit can therefore never be created *or*
destroyed by the C port — the exact "broken magnet" failure of Round 18 is structurally
impossible as long as the C screen never false-rejects, which controls V1–V3 (§8) prove.

**Expected candidate volume.** Per-seed null tail from the pair Gumbel cell
(`mu=2.4199696989376633`, `beta=0.2695287952432638`):
`P(pmax >= 5.0) ≈ exp(−(5.0−mu)/beta) ≈ 6.95e−5` ⇒ ≈ **3.0e5 candidates over 2^32**.
Python stage_b at ~10–30/s clears that in hours (run it concurrently, tailing the JSONL).

## 1. Seed space and keystream derivation (Py2.7 MT19937 — verbatim semantics)

A **word** is an unsigned 32-bit integer `w ∈ [0, 2^32)`. It is fed to the generator as

```python
r = MT19937(); r.init_by_array([w] if w else [0])     # runner.word_stream — [0]≡[w] at w=0
```

This is EXACTLY CPython 2.7 `random.seed(w)` for this range (`random_seed` splits
`abs(w)` into 32-bit chunks from the right ⇒ a single-element key `[w]`; `[0]` for 0).
Python-3 int seeding is identical for ints; the Py2-vs-Py3 divergence (string hashing)
does not enter this lane. `wordsize` is irrelevant for int seeds.

### 1.1 MT19937 core (mt19937ar, as carried verbatim by CPython 2.7 `_randommodule.c`)

Constants: `N=624, M=397, MATRIX_A=0x9908B0DF, UPPER=0x80000000, LOWER=0x7FFFFFFF`.
All arithmetic mod 2^32 (use `uint32_t`).

```c
init_genrand(s):
    mt[0] = s;
    for (i = 1; i < 624; i++)
        mt[i] = 1812433253u * (mt[i-1] ^ (mt[i-1] >> 30)) + i;
    index = 624;

init_by_array(key[], klen):                 // here klen == 1, key[0] == w
    init_genrand(19650218u);
    i = 1; j = 0;
    for (k = max(624, klen); k; k--) {
        mt[i] = (mt[i] ^ ((mt[i-1] ^ (mt[i-1] >> 30)) * 1664525u)) + key[j] + j;
        i++; j++;
        if (i >= 624) { mt[0] = mt[623]; i = 1; }
        if (j >= klen) j = 0;
    }
    for (k = 623; k; k--) {
        mt[i] = (mt[i] ^ ((mt[i-1] ^ (mt[i-1] >> 30)) * 1566083941u)) - i;
        i++;
        if (i >= 624) { mt[0] = mt[623]; i = 1; }
    }
    mt[0] = 0x80000000u;
    index = 624;

genrand_uint32():
    if (index >= 624) {  // block refill, standard twist with MATRIX_A on odd y
        for (kk = 0; kk < 227; kk++) {
            y = (mt[kk] & UPPER) | (mt[kk+1] & LOWER);
            mt[kk] = mt[kk+397] ^ (y >> 1) ^ ((y & 1) ? MATRIX_A : 0);
        }
        for (kk = 227; kk < 623; kk++) {
            y = (mt[kk] & UPPER) | (mt[kk+1] & LOWER);
            mt[kk] = mt[kk-227] ^ (y >> 1) ^ ((y & 1) ? MATRIX_A : 0);
        }
        y = (mt[623] & UPPER) | (mt[0] & LOWER);
        mt[623] = mt[396] ^ (y >> 1) ^ ((y & 1) ? MATRIX_A : 0);
        index = 0;
    }
    y = mt[index++];
    y ^= y >> 11;
    y ^= (y << 7)  & 0x9D2C5680u;
    y ^= (y << 15) & 0xEFC60000u;
    y ^= y >> 18;
    return y;

random():   // genrand_res53 — bit-exact double
    a = genrand_uint32() >> 5;                       // 27 bits
    b = genrand_uint32() >> 6;                       // 26 bits
    return (a * 67108864.0 + b) * (1.0 / 9007199254740992.0);
```

### 1.2 Reducer — `random29` (MODE="random29"; the ONLY reducer in S1)

```c
ks[i] = (int)(random() * 29.0);      // C truncation toward zero == Python int()
```

Exactly **2 MT draws per rune, no rejection**. The reducer output is a prefix-stable
stream: `word_stream(w, 128)` is the first 128 of `word_stream(w, 784)`.
Stage-A keystream length: `L_SCREEN*6 + 64 = 784` runes.
(Other Py2.7-collapse fact, R19-G3 V5: `randrange(29) == randint(0,28) == choice(range(29))
== int(random()*29)` in 2.7 — random29 covers all four idioms at once.)

## 3. Decode relation — driftbeam `keyskip2`, preset `"pair"`

Frozen call (from `runner.stage_a`):

```python
DB.beam_decode(C_SCREEN, K, sign=-1, o=0, beam_w=64,
               mode="keyskip2", max_skip=8, max_free=0, lam=0.0,
               lam_explained=0.0, start_slack=0)
```

`N = 29`. Transliteration table (index → string; 7 runes are 2 chars — all scoring on the
translit STRING, all recovery on rune INDICES):

```
0:F 1:U 2:TH 3:O 4:R 5:C 6:G 7:W 8:H 9:N 10:I 11:J 12:EO 13:P 14:X 15:S 16:T
17:B 18:E 19:M 20:L 21:NG 22:OE 23:D 24:A 25:AE 26:Y 27:IA 28:EA
```

### 3.1 Keystream zero-padding (load-bearing!)

`driftbeam` pads: since `o + L + max_skip*L = 0 + 120 + 960 = 1080 >= len(K) = 784`,

```
Kx = K ++ [0] * (L*(max_skip+1) + 8) = 784 reduced runes ++ 1088 zeros   (len 1872)
```

A beam path that drifts past index 783 reads key value 0 (rune F). The C engine MUST
reproduce this padding or deep-skip paths diverge.

### 3.2 State and recurrence

Hypothesis tuple: `(cum_score, quad_cum, acc, tail, nchars, n_unexplained, backptr)` where
`acc` = key index consumed by the latest rune, `tail` = last ≤3 chars of the running
transliteration, `nchars` = translit length so far. With `lam = 0`, `cum_score ==
quad_cum` (keep both anyway; sort key is `cum_score`).

**Init** (`start_slack=0`): one hypothesis. `p0 = (C[0] + sign*Kx[0]) mod 29 =
(C[0] − Kx[0]) mod 29`, `tail = TRANS[p0]`, scores 0.

**Step i = 1 … 119.** Let `ci = C[i]`, `delta = (sign*(C[i−1] − ci)) mod 29`
(sign=−1 ⇒ `delta = (ci − C[i−1]) mod 29`). Precompute per step, indexed by key value
`k ∈ [0,29)`:

```
pmap[k] = (ci + sign*k) mod 29      // plaintext rune if accepted key value is k
tmap[k] = TRANS[pmap[k]]            // its transliteration (1–2 chars)
vmap[k] = (k − delta) mod 29        // the ONE key value every skipped slot must hold
```

For each surviving hypothesis with accepted index `pa`: `base = pa + 1`. A 29-bin
histogram `cnt[]` (zeroed between hypotheses — see reset below) counts key values seen in
the *skipped-slot* positions. Loop `dsk = 0 … 8` with `acc = base + dsk` (`break` if
`acc >= len(Kx)`):

- **Histogram update (pair mode):** if `dsk > 0` and `dsk` is ODD:
  `cnt[Kx[acc−1]] += 1; maxcnt = max(maxcnt, cnt[Kx[acc−1]])`. (Even dsk does NOT update.)
- **Representability (pair mode):** if `dsk > 0` and `dsk` is odd → `continue`
  (only EVEN total advances are representable: skips come in pairs). For even `dsk > 0`,
  `need = dsk >> 1`. Prune: if `need − maxcnt > max_free (=0)` → `break` (monotone).
- **Consistency:** `nun = need − cnt[vmap[Kx[acc]]]`; if `nun > 0` → reject this `dsk`.
  (Semantics: each *pair* of burned key slots must have its FIRST slot hold the value
  that would have reproduced the previous cipher rune — exact for the `skip_by_two`
  rejection loop; the pair's second slot is unconstrained.)
- **Emit child:** plaintext rune `pmap[Kx[acc]]`, translit `t = tmap[Kx[acc]]`
  (`la = len(t)`), incremental quadgram total `tot` per §3.3,
  child = `(sc + tot, qc + tot, acc, last3(tail+t), nchars+la, nun_tot+nun, ptr)`.
- **Histogram reset** after the dsk loop: for the incremented entries only —
  `for (m = base; m < hi; m += 2) cnt[Kx[m]] = 0;` where `hi` = highest `acc` reached.

**Prune:** sort ALL children by `cum_score` DESCENDING with a **STABLE** sort (Python
`list.sort` is stable; insertion order = parent-beam-rank-major, then dsk-ascending);
keep the top **64**. Stability is the only tie-break — implement it (index-tagged sort or
stable mergesort), otherwise tied scores can reorder the beam. (Divergence risk is
bounded by the §0 margin, but exact-match against vectors.json requires it.)

**Finish:** best = `beams[0]`. Walk backpointers for `plain_idx` (length 120).
`score = quad_cum / (nchars − 3)` — nchars is TRANSLIT length (120–240 chars), not 120.

### 3.3 Incremental quadgram scoring (steers the beam only)

Quadgram model `src/lp/score.py`: `data/english_quadgrams.txt` (79,495 entries), each
`d[q] = log10(count) − log10(total)`, `total = 7266795`,
`floor = log10(0.01) − log10(total) = −8.861342908696827` for unseen quadgrams. Load
into a 26^4 double table (A=0…Z=25), default floor. Per emitted rune with `s2 = tail + t`
(tail = last ≤3 chars, so `len(s2) ≤ 5`), `L1 = nchars` before the append:

- if `L1 < 3` (string still short; `s2` is the ENTIRE translit so far):
  `tot = Σ_{e=4..L1+la} d[s2[e−4 : e]]` (skip terms with `e−4 < 0`, i.e. none once e≥4);
- elif `la == 1`: `s2` is exactly 4 chars → `tot = d[s2]`;
- else (`la == 2`): `s2` is 5 chars → `tot = d[s2[0:4]] + d[s2[1:5]]`.

Sum in double, in that order. `quad_cum` accumulates these; the FINAL reported score is
`quad_cum/(nchars−3)` (unpenalised; with lam=0 penalty never applies anyway).

## 4. The score — panel-max `pmax` (the ONLY number the C engine gates on)

From `adjudicate.adjudicate(plain_idx)`, pmax path only (skip `en/ioc/mds/h2/zl` in C —
they are recomputed by Python on every candidate via SWEEPROW/3):

```
x = plain_idx (120 rune indices)
f_i = x[i]*841 + x[i+1]*29 + x[i+2]          for i = 0 … 117      (118 trigrams)
raw[r] = (1/118) * Σ_i LM[r][f_i]            LM float32, accumulate in double
z[r]   = (raw[r] − mu[r]) / sd[r]            r = 0 … 8
pmax   = max_r z[r]
```

- **LM table:** `analysis/round19/I2/models/panel.npz` key `LM`, reshaped to
  `(9, 24389)` float32 (row = register, in this order:
  `EN_MODERN EN_KJV LP1_REAL LATIN OE DE CY EN_HALFVOWEL EN_NOVOWEL`). The .npz is
  gitignored/rebuildable (`round19/I2/build_models.py`); the P1 lane must export it to a
  flat binary (`panel_lm.f32`, 9×24389 little-endian float32, row-major) **from the same
  panel.npz that generated vectors.json** and record its sha256 alongside.
- **Calibration at n=120** (length not on the grid → log-interpolated between 96 and 128;
  the interpolation is FROZEN into constants, C does not reimplement `cal()`):
  `mu`, `sd` per register are in `vectors.json["constants"]["panel_mu_n120"/"panel_sd_n120"]`
  (e.g. mu[0] = −1.9926754391005939, sd[0] = 0.05827432252754414).
- numpy's `.mean()` uses pairwise summation; a naive double loop differs by ≲1e−13 at
  n=118 — inside the V1 tolerance (1e−9). Either summation order is acceptable.

### 4.1 Bars (computed once, hard-coded as doubles)

```
claim bar (pair, N=1e6, alpha=0.01):
    bar = mu_c + beta_c * (ln(1e6) − ln(−ln(0.99)))
        = 2.4199696989376633 + 0.2695287952432638 * 18.415703...
        = 7.383520294328688                      (R25's "7.384")
cell: calib19.json "I19:driftbeam.pair+I2|pmax|L120"  (M=60000, PROVISIONAL)
CAND_BAR = 5.0        (== R25 SCREEN_BAR; < claim_bar − 1.5 = 5.883520294328688)
```

The C engine flags `pmax >= 5.0`. It NEVER compares against 7.3835 — that comparison
belongs to Python's `panelmax20.panelmax_bar` inside `hitfn20`.

## 5. The Python hit gate (unchanged; documented for completeness)

`runner.stage_b(w, 10**6)` → `hitfn20.evaluate(HitDecode(C=C_HIT[240], K=word_stream(w,1504),
o=0, preset="pair", n_round_adjudicated=1e6))`, beam_w=400. HIT iff ALL of:

1. `pmax >= panelmax_bar("pair", 1e6, 0.01) = 7.383520294328688`;
2. rune-INDEX recovery ≥ 0.90 — real candidates: held-out self-consistency
   (fit key phase on first 1/4 via `ptr_end+1`, re-decode the 3/4 tail, compare to the
   full decode's own tail); plants: strict vs `truth_idx`;
3. held-out 3/4 recovery ≥ 0.90 (same computation).

Score alone is never a hit. A survivor is **FLAGGED-FOR-ORACLE, never auto-certified**
(R21-L1). Every candidate — hit or not — gets a full SWEEPROW/3 row (all doctrine-R3
language-agnostic statistics), which is this sweep's R3 compliance path.

### 5.1 Planted-seed self-test (the positive control that gates every run)

`runner.planted_seed_selftest(seed=777)`: transliterate
`data/keys/self_reliance.txt` → `eng_to_idx[5000:5240]` (240 runes), encipher under
**skip_by_two** (`c = (p + K[j]) % 29`; while `c == c_prev` and `random.Random(777).random()
< 0.83`: `j += 2` and retry; then emit, `j += 1`), keystream = `word_stream(777, 1504)`.
Decode with the same seed via hitfn20's strict `truth_idx` path. Measured (2026-09-07):
`recovery 1.000, heldout 1.000, pmax 25.239 vs bar 7.384, HIT=True`. The full construct
(truth_idx, cipher_idx, keystream head) is frozen in `vectors.json["planted_selftest"]`.

## 6. Sweep bookkeeping (checkpoints, coverage, exclusion)

- **Checkpoint format** (keep `progress_w{i}.json`-compatible so `--status` tooling
  ports over): `{worker, band_start, band_end, cursor, seeds_done,
  seeds_skipped_excluded, best_pmax, best_word, flagged_survivors, done}`. Atomic write
  (tmp + rename), cadence ≥ 30 s — repo lives on /mnt/c (slow I/O), keep writes small.
- **Coverage** = Σ over workers of `(cursor − band_start)` / 2^32. R27-S1 restarts from
  0 and **drops the R25 exclusion set** (the 45,975 prior+neighbourhood words and the
  [0, 200000) dense baseline are simply re-swept): re-covering R25's 0.5015%
  (21.5M words) costs minutes at C speed and removes every double-count/gap risk. So
  `seeds_skipped_excluded` stays 0 and coverage is pure cursor arithmetic.
- **Extra persisted aggregates** (cheap, makes the null re-interpretable): per worker, a
  pmax histogram (bins of 0.01 over [0, 26), uint64 counts) and a running top-1024
  `(seed, pmax)` list, flushed at checkpoint time.
- **candidates.jsonl**: one line `{"seed": w, "pmax": <double>}` per flag, append-only,
  fsync'd at checkpoint cadence. Python re-scorer consumes it (idempotent by seed).

## 7. Throughput target

Python does ~330 seeds/s/core (R25 measured 1650–1966 aggregate on 6 cores). Budget per
seed in C: keystream 1568 MT draws (~2 µs) + beam 119 steps × ≤64 beams × short dsk loop
(dominant) + 9×118 table gathers. Conservative target **≥ 5,000 seeds/s/core ⇒ ≥ 30k/s
aggregate ⇒ 2^32 in ≤ 40 wall-hours on 6 cores**; plausibly 3–10× better. If measured
throughput < 2,000/s/core, profile before launching the full sweep (kill-condition K1 in
PREREG).

  recorded repr; `ptr_end`, `n_skips`, `nchars` exact.

  `pmax = 17.93115850976196` (±1e−9) → candidate emitted (margin over CAND_BAR: 12.9).
- **V3 (end-to-end drill):** sweep the band [2149309680, 2149309700); best word must be
  2149309687 at pmax 6.825835461843649; then run the Python self-test
  (`parallel_grind.py --self-test`) → `recovery 1.000 / HIT=True`.
- **V4 (candidate-path liveness):** inject a fake line into candidates.jsonl and show the
  Python re-scorer picks it up and emits a SWEEPROW/3 row; then plant-through: seed 777's
  synthetic construct through stage_b fires HIT and the FLAGGED-FOR-ORACLE stop path.

## 9. What the C engine must NOT do

No hit decision. No recovery computation. No held-out logic. No comparison against
7.3835. No auto-certification ever — any Python-side HIT is FLAGGED-FOR-ORACLE (R21-L1).
No silent preset/bars substitution (the L7-C.3 error). No skipping V1–V4 after any code
change to the hot path.
