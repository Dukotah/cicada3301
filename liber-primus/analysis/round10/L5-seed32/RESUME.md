# How to resume the full 32-bit seed sweep

Everything here is in `liber-primus/analysis/round10/L5-seed32/`. Nothing outside this
folder was modified. Read `FINDINGS.md` first — it argues that finishing this sweep at the
Round-8 threshold is **not** decisive and says what to change before spending the CPU.

## Build

```bash
wsl -d Ubuntu -- bash -lc 'cd /mnt/c/Users/dukot/projects/cicada3301/liber-primus/analysis/round10/L5-seed32 && \
  gcc -O3 -march=native -fopenmp -o sweep32  sweep32.c  -lm && \
  gcc -O3 -march=native -fopenmp -o sweep32x sweep32x.c -lm'
```

`sweep32` = Round 8's `sweep.c` with two changes only (env-configurable data paths;
`MAXK` 320→96, A/B-verified byte-identical). `sweep32x` = the same plus generators 10–13.

## Validate before trusting any run

```bash
./sweep32x selftest        # must print "selftest: 14/14 generators recovered"
./validate_gens.sh         # must print "HARNESS GATE: PASS"
```

`validate_gens.sh` re-derives generators 10–13 against real `perl`, glibc `lrand48`, real
`ruby`, and an independent Python implementation of Marsaglia's recurrence — 5 seeds ×
2000 draws each. A generator that fails this is not swept.

## Advance coverage (resumable, checkpointed)

```bash
./run32.sh <gen 0-9> <real|shufa|shufb> [n_chunks]
```

* Chunk size is 2^26 seeds. One TSV row per completed chunk in `chunks_<tag>.tsv`.
* Resume is automatic: the driver reads the highest `hi` already logged for that
  `(gen, tag)` pair and starts there. Re-running the same command never recomputes.
* `n_chunks` omitted ⇒ run that generator to the end of the 32-bit space.
* Threads: `OMP_NUM_THREADS` defaults to 32, measured optimum on this box
  (Intel Core Ultra 7 258V, WSL2 sees 6 CPUs; oversubscribing to 32 is 3.8× faster than 6).

Do **not** use Round 8's `run_full32.sh`: it appends one line per *generator*, so a kill
mid-generator loses hours of work with no record. That is exactly what happened — its log
holds 2 lines and no `DONE`, and the first generator in its own iteration order (gen 0,
glibc, the highest-prior one) is missing from it entirely.

## Cost of finishing, measured on this box

2^26 seeds ≈ 55 s for generator 0 at `OMP_NUM_THREADS=32` ⇒ **1.17M seeds/s**, so a full
32-bit pass over generator 0 is **64 chunks ≈ 61 minutes**. Generators differ in cost;
scaling Round 8's per-generator time-seed timings gives:

| gen | relative cost | full-32 wall clock, this box |
|---|---|---|
| 0 | 1.00 | 1.0 h |
| 1 | 0.92 | 0.9 h |
| 2 | 1.77 | 1.8 h |
| 4 | 0.71 | 0.7 h |
| 6 | 1.80 | 1.8 h |
| 7 | 1.27 | 1.3 h |
| 8 | 2.92 | 3.0 h |
| 9 | 0.77 | 0.8 h |

**Remaining for the 8 unfinished Round-8 generators: ≈ 11.3 hours wall / ≈ 1.5 CPU-days.**
Adding generators 10–13 over the full space costs a further ≈ 4 hours.
It is embarrassingly parallel — each `(gen, chunk)` is independent.

## Before you spend that: read `FINDINGS.md` §2

The pre-registered `-12.5` threshold does **not** survive to the completed sweep's N. Run
with a corrected threshold or the run answers nothing. The corrected family-wise thresholds
are printed by `python3 nullcurve.py`.
