# PREREG addendum 1 (R44 bookcipher) - dated 2026-10-31, written BEFORE any R44 output

Why: PREREG section 7 said a blocked cell found present-and-complete with a cheap re-score would be run "with the same control-first discipline". The artefact search (done after PREREG, read-only, before any R44 scoring) found that the 5 books of `campaign XVII / bookcipher` (`analysis/bookcipher/books/{kjv,mabinogion,miltonPL,blake,agrippa}.txt`) and the scheme code (`analysis/bookcipher/bookcipher.py`) ARE in the working tree. The six books of `bookcipher_expand.py` (liber_al, kybalion, blake_mhh, goetia_g, thunder, thomas_gnosis) are NOT present (searched analysis/, archive/, corpus/, data/). So the reading R44 as `bookcipher.py` defines it can be re-scored; the expanded set cannot.

Family (R44-bookcipher.py): book x reverse x offset x scheme exactly as `bookcipher.py`: books kjv, mabinogion, miltonPL, blake, agrippa (`load_book` as in the script; a book with < 5,000 letters is skipped); rev in {F,T}; off in (0,1000,12345) for L1 (letter skip by idx+1), L2 (letter skip by prime), W1 (word skip by idx+1, concatenated words), W2 (word skip by prime); and G (base-29 pair -> absolute letter, once per rev). Per book 2 x (3 x 4 + 1) = 26 units, 130 units in all. Outputs are the first 4,000 letters (L, G) or 800 words (W); each output string is parsed to rune indices by `gp.keyword_to_indices` (the repo's greedy parse) and scored by panel-R36 through the unchanged direct machinery (`lib.pm_many`). Units with < 32 runes are excluded.

Null: the pointer stream (the 12,956 unsolved runes, as `bookcipher.runes()` builds it) replaced by `bars_matched.matched_shuffle(UN, block, Random(60000+j))`, block 100 / 250 / 1000, D = 1000 per block, the whole family re-derived on each draw. Statistics, alpha = 0.0025 and the "decision p = max of three, both statistics" rule as in PREREG section 5 (one family, level = the 130 units).

Control (pointer-crafted, the actual hit shape): for L1, L2 and G units a target letter string (the transliteration of a held-out test-half text, 3,000 letters, registers EN_MODERN / LATIN / EN_NOVOWEL cycling by unit index) is turned into a pointer stream whose scheme output IS the target (L1: smallest idx+1 in 1..29 that lands on the next target letter; L2: the first idx whose prime step lands on it; G: an occurrence of the letter in the first 841 book letters, the only range G can reach; where no step lands, step 1 is used and the miss counts against recovery), reversed when rev=T, and then run through the real scheme code and the real parse/score path. For W1 and W2 a plant is a book passage read by the scheme with idx in {0,1,2} (steps 1-3; English word concatenation by construction; registers EN only - this limitation is reported). Recognised iff letter-level recovery >= 0.90 AND plant pmax > the maximum over all 3 x 1000 null draws of the family-best pmax. Gate: every plant recognised -> `passed`; otherwise `failed` with counts. Limits stated up front: G can reach only the first 841 letters of a book; planted W control covers EN only.

Kill: if the first 6 L1 plants do not reach recovery >= 0.90 the crafting is wrong and the R44 scoring is not run. Same machinery as run_c1.py (`lib.py`, `camp7.py` not used), one process, nproc=1, RAM rule, append-mode, no git.
